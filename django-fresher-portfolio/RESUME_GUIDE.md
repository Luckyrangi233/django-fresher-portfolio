# Fresher Resume Guide

Keep the resume to one page when practical. Focus on skills you can explain and evidence a reader can inspect. Replace all brackets and remove any item you cannot defend in a conversation.

## Suggested layout

**[Full name]** | [City, Country] | [Email] | [Phone] | [GitHub URL] | [LinkedIn URL]

**Profile**  Entry-level Python/Django developer with hands-on practice building [project type], writing tests, and [one verified strength]. Seeking a junior role where I can [relevant contribution].

**Skills**  Python [level you can demonstrate], Django, HTML/CSS, SQL, Git/GitHub, [testing tools actually used], [other real skills]. Avoid skill bars and long unverified keyword lists.

**Projects**  Put your best relevant project first. Include a working repository link and live demo only if genuinely available.

**Education**  [Credential], [institution], [dates] | [Relevant coursework or achievement]

**Experience / volunteering**  Include paid work, internships, community work, tutoring, or other evidence of reliability and teamwork. Describe your own contribution.

## Project entry template

**HelpDesk | Django, Python, SQLite, HTML** · [Repository URL]

- Built an authenticated ticket workflow for [validated user group / clearly stated target user], supporting request creation, priority, status tracking, and filtering.
- Restricted ticket queries to their owner and added automated tests for login and cross-user access behavior.
- [Add verified result, e.g. “Validated the workflow with N volunteer users; they completed task X” only when true.] 

Use action + feature + reason/evidence. Do not add “reduced work by 50%” unless you recorded a meaningful before/after measurement and can explain its method. Do not say “production-ready” for this learning starter.

## Make the work shortlist-worthy

- Finish one coherent project; provide setup instructions that work from a clean clone.
- Keep commit history readable and remove database files, secrets, and private data.
- Add real screenshots, test instructions, known limitations, and a short problem statement.
- Prepare a 3-minute demo and practice explaining the database relationship and access-control decision.
- Tailor skill words to the job description only when you have actually used or studied them.
- Ask someone to review the resume and follow the employer's requested application format.

## README evidence checklist

Problem/user · validation or hypothesis · core features · architecture/data model · local setup · tests and results · screenshots · limitations/security notes · next steps · deployment link (optional and verified).
